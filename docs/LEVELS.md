# Cargo Shift 关卡设计

当前 18 关均为原创紧凑关卡，采用经典推箱子的仓库结构：共用窄口、换边绕行、目标填充顺序、临时停车位和多箱交替调度。所有地图都限制在 10×8 的单屏区域内，使用 3～6 只箱子；最少移动步数从 24 步逐步增加到 118 步，最少推动次数为 10～38。

## 设计与生成

参考阅读：[经典 Sokoban 地图合集](https://github.com/begoon/sokoban-maps/blob/master/maps/sokoban-maps-60-plain.txt)。经典地图常将目标仓库与箱子区用狭窄通道连接；本项目借鉴这些设计原则，重新设计适合单屏游玩的地图。

房间骨架与候选筛选由本项目完成。`tools/create_cargo_classic_levels.py` 从完成状态对逆向推动状态做广度优先搜索，选择推动距离较远的候选，而非短距离随机打乱。房间骨架、种子、变换、设计主题及筛选指标保存在 `assets/cargo_shift/classic-design.json`；`levels.json` 为最终地图。

每关再由两个独立的正向求解过程验证：A* 求最少总移动步数；将自由行走折叠后的 BFS 求最少推动次数。下表两项最优值分别计算，不保证同一条路线同时达到两项最优。移动步数用来编排进度，推动次数作为规划难度的辅助指标；两者不能完全代替真人试玩。

## 数据维护

最终地图保存在 `assets/cargo_shift/levels.json`。修改后运行：

```sh
make assets
make solve
make verify
```

`map` 使用 `#` 表示墙、空格表示地板、`.` 表示目标、`$` 表示箱子、`@` 表示玩家、`*` 表示目标上的箱子、`+` 表示目标上的玩家。地图最大为 10×8，必须为矩形并由墙完整包围；每关只能有一个玩家，箱子数必须与目标数相等。

`make assets` 会检查地图尺寸、边界、字符、玩家数量以及箱子与目标数量；`make solve` 会重新计算两类最优指标并更新主机测试使用的解答。`tools/create_cargo_classic_levels.py` 用于从设计配方重建全部关卡，会覆盖现有 `levels.json`。

所有关卡均已通过 ROM 输入流程通关。难度表、设计说明和验证指标只在文档中提供，游戏画面保持简洁，不显示攻略、PAR、撤销余量或卡死提示。
